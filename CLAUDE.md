# Tornet

Simulering av skyskrapan Tornet med 8 hissar (styrsystemet heter Hiss-O-Matic 3000) i 16-bitars pixelgrafik och 90-talsstil (paletten "Kontor 95"). Fokus är en **rolig och detaljerad simulering att titta på**, inte spelmekanik. Dockhusprincipen: huset sköter sig självt – driftchefen (`chief.js`) tar alla beslut och berättar varför – och spelaren kan ta över ett beslut eller framkalla vad som helst. All text i koden (kommentarer, loggar, simuleringens texter) skrivs på **svenska**; spelet visar dem på **svenska** som standard och kan byta till engelska sömlöst (`lang.js`, se nedan).

## Köra

```bash
python3 serve.py          # http://localhost:8123 (no-cache-server, krävs för att ändringar ska synas)
```

Servern lyssnar bara på den egna datorn (`--lan` = även nätverket, t.ex. mobilen) och lämnar bara ut spelets filer: `ALLOWED` i `serve.py` – **en ny mapp som spelet laddar måste läggas till där**, annars ger den 404. `python3 serve.py --auto-stop` (så startar `~/Projekt/Tornet.app` spelet) stänger dessutom av sig själv 5 min efter att spelet tystnat (spelet anropar `/ping` var 30:e sekund, `main.js`) eller efter 12 h. Spelet hämtar inget utifrån: typsnittet VT323 ligger i `fonts/` (OFL).

Ingen byggprocess: webbläsaren laddar `src/*.js` som ES-moduler direkt. Förhandsvisning: `.claude/launch.json` → konfigurationen `hiss`.

Node (Homebrew) behövs bara för tester/typkontroll. I ett skal utan profil måste brew läsas in först:

```bash
eval "$(/opt/homebrew/bin/brew shellenv)"
npm test            # hela sviten i Node, parallellt, en tråd per kärna (--jobs=N, --jobs=1 = en tråd)
npm run typecheck   # tsc på JSDoc-typer (jsconfig.json)
npm run check       # båda
npm run quick       # snabbläget: typkontroll + sviten med färre slumpade dygn, utan styrlogikernas statistiska jämförelser (ungefär halva tiden)
npm run golden      # skriv om tests/golden.json efter AVSIKTLIGA beteendeändringar
npm run bench       # simuleringens fart (steg/s per styrlogik)
npm run lang        # svenska texter i koden som saknar engelsk mall i lang-en.js
npm run league      # styrlogikerna mot varandra: väntetid (p50/p95/p99), kWh, trappa, ETA-fel; --save=x / --cmp=x; --flytt --flyttval=auto|varu|balk; --utanchef
```

Samma testsvit körs i webbläsaren på `/tests.html` (`/tests.html?quick` = snabbläget). På GitHub kör `.github/workflows/check.yml` `npm run check` vid push till `main` och vid pull request (inte när bara `.md`-filer ändrats) – Actions-minuterna räcker inte till mer, så CI är ingen ersättning för att köra testerna själv.

## Arkitektur

**Simulering** (rör aldrig DOM eller canvas, körs headless i Node):

| Fil | Ansvar |
|---|---|
| `config.js` | `BUILDING` (våningar + hissar som data), `THEME_INFO` (namn, platser), all härledd geometri och konstanter |

| `util.js` | små hjälpfunktioner som både simuleringen och grafiken använder: `fl` (våningens etikett), `clamp`, `ARR`/`K` (riktning), `esc` (html), `hex2rgb`/`mix` (färger) |

Simuleringen skriver svenska och vet aldrig vilket språk som visas; gränssnittet översätter allt i det ögonblick det visas – `trDom` efter varje `innerHTML` i panelen, textskylten, verktygstipset och overlayen, `tr` i pixelgrafikens text (`textW`/`textSprite` i pixart.js) och i rundvisningen och Berits röst. Därför byter även gamla loggrader språk direkt. Översättningarna i `lang-en.js`: svensk mall → engelsk mall med värden `{0}`, `{n}` … som i sin tur översätts; en text utan egen mall delas vid avskiljarna (` · `, ` – `, `: `, meningar …) och sätts ihop av de bitar som har mallar (den indelning som lämnar minst svenska vinner); emoji och versaler (skyltar) klaras av. Ny svensk text i koden = en post i `lang-en.js` (`npm run lang` listar det som saknas); lagren i pixcore.js har språket i nyckeln), `input.js` (klick, tangenter och alla knappar: `doAction` för `data-act`, nya gränssnittsåtgärder läggs i `extraActions`; vänsterklick i bilden följer person, hiss, korridor (nästa person därinne) eller våning – det finns ingen högerklicksmeny), `main.js`.

Driftcentralen (kontrollrummet) ritas i hallen på våningen med taggen `control` (`CONTROL` i config, P1): en skärm per hiss, larmljus, kontrollbordet med driftchefen och bildproducentens skärm; repliken (`S.chief.say`) rullar i fönstrets textremsa och syns som pratbubbla (`drawChiefPx`, där chefen är). Regissören klipper dit när chefen fattar ett beslut. Personalrummet ritas likadant på våningen med taggen `break` (`BREAK`, P2). Personalen syns på sin plats efter `spot.win` (`inWindow`/`winPos` i render.js): i fönstren (`control`, `break`), bakom receptionsdisken, i gondolen, på takterrassen eller stående i hallen (`hall`).

Det statiska (stadssiluetten, tegel, fasadfönster, schakt, rampen) ritas i lager via `layer()` i `pixcore.js` och ritas bara om när nyckeln ändras (natten i 32 steg, strömmen, bredden). Något som rör sig eller beror på personer får aldrig ritas i ett lager. Ritytan (`g`, `lo`, `X0`, `CY`) byts bara i pixcore.js (`layer`, `beginFrame`); de andra pix-modulerna läser den, och tillstånd för en bildruta nollställs via funktioner i modulen som äger det (`resetCallAt`, `countOcc` …).

Bilden börjar vid `LAND_X0` och varje våning ritas som en hall framför schakten med en korridor (`DOOR_X`) in mot rummen (längst in syns en glimt av rummet, `GLIMPSE`; i entrén en karuselldörr, reception och rulltrappan till mellanplanet). Hallens bredd är bara grafik – `TRAIN_X0` är fast eftersom simuleringen använder det. Schakten har stängda landningsdörrar vid varje hållplats, och våningsdisplayerna lyser bara där något händer. Folk i rummen ritas inte; `landPos` räknar ut var de syns i hallen (kön pressas ihop mot korridoren, gång in/ut syns bara sista/första biten) – ren grafik, simuleringens `p.x` ändras aldrig. Text i hallen bokar plats (`reserve`/`place` i pixcore.js): skyltar först, sedan pratbubblor, tankebubblor (de som väntar på samma hiss till samma våning delar en bubbla) och repliker – det som inte får plats flyttas eller ritas inte. Ljudeffekter i `S.fx` med samma text på samma våning slås ihop till en ("×n"). Allt ritas på ett rutnät i låg upplösning (1 pixel = `PX` = 2 världsenheter) som skalas upp utan utjämning; skärmkoordinater räknas om med `VIEW.x0` (se `toWorld`, `placeCarPop`).

Allt följer paletten **Kontor 95**: byggnadsfärger i `PAL` (`pixpal.js`), hissarnas `color` och våningarnas `acc` i `config.js`, och gränssnittet i `style.css` (blågrönt skrivbord, grå fönster med upphöjda/nedsänkta kanter, marinblå titelrader, DOS-svarta skärmar). Text på en färgad yta får färg via `PAL.on(färg)`.

Det finns ingen topplist, statusrad, låda eller högerklicksmeny: hela gränssnittet utom bilden är **kontrollpanelen** `#side` till vänster (fast bredd, så att bilden inte skalas om; aldrig flytande över bilden – den får inte täcka hallarna). Enda undantaget är den halvgenomskinliga textskylten `#lower` längst ner i bilden: kameran räknar med den (`VIEW.padB`, `seeH()` i view.js – det man följer hålls ovanför skylten, och bilden kan scrollas `padB` längre ner). Knapparna är ikoner (`ikon()` i hud.js) med namn och förklaring i verktygstipset; val mellan lägen (styrlogik, slumpen, incidentkortens val) och incidentkortens huvudknappar behåller texten. Panelen består av block (`ORDER` i panels.js: uppspelning med paus/fart, kamerans verktyg (regissör, biograf, namnbrickor, ljud), ? hjälp och dygnets stapel – händelser – det du följer – driftradion – framkalla – styrning – dagen – vy – länkar) som vart och ett får läget `full`, `row` eller `link` efter situationen (`layout`): lugnt = allt utfällt; en incident eller förvarning = korten överst, driftradion på en rad, framkalla och styrning som länkar längst ner; följer du en person, hiss eller våning får den ett eget block med det som går att göra just där (framkalla fel i hissen, brand/besökare/buss på våningen). Får något inte plats krymper blocken i `SQUEEZE`-ordning; läget räknas om när situationen ändras (`UI.key`). Länkarna öppnar vyer i panelen (register, logg, inställningar, resultat); Esc stänger vyn eller slutar följa. Incidentkorten är utfällda tills spelaren fäller ihop dem (`foldInc`), informationsrutor fälls ihop av sig själva efter en stund. Incidentrutan har två sorters kort: **incidenter** som spelaren kan åtgärda (brand, ström, storm, överhettad motor – rutan blinkar) och **informationsrutor** som bara berättar och kan stängas (flyttdag, ambulans och `S.notices` via `notice()` i state.js: kall dag, snubbel, extra tekniker). Varje kort har knappar som visar händelsen (`show:våning` följer våningen, `follow:hiss`). Stängda rutor ligger i `S.dismissed` (bara gränssnittet).

## Regler som inte får brytas

- **Determinism.** Simuleringen får bara använda `rng.js`-slumpen (`rng/rand/pick…` ur en `stream`), aldrig `Math.random`/`vrand` eller väggklocka. Strömmarna är oberoende: ett slumptal till i ett delsystem flyttar inte de andra, så du behöver inte vakta på hur många slumptal något drar. Nytt delsystem som kan ändras för sig = ny ström (ett namn får bara användas en gång). Ankomsterna (`anställda`, `besökare`, `gestalt`, `tåg`, `bud` …) får aldrig dela ström med något som beror på styrlogiken, och får inte dras bakom ett villkor som gör det (`if (kö < 3 && rng() …)`) – då ser alla styrlogiker samma dygn: samma personer på samma sekunder (testet Slumpströmmar). `makePerson` drar ur `inkallade` om inget annat sägs; bara `spawnEmployee`/`spawnVisitor` använder `gestalt`. Grafik får bara använda `vrand/vpick` och får aldrig ändra simuleringstillstånd. Samma frö (`?seed=`) ⇒ identiskt dygn; testet för bildfrekvens, determinismtestet och facit vaktar detta.
- **Fast tidssteg:** `DT = 1/30`. Logik som beror på tid använder `dt`/`S.t`, aldrig bildrutor.
- **Dygnsskiftet** (`S.roll`): `'mjuk'` (spelet – alltid, start.js; spelaren kan inte välja) = kl 06 kör `rollDay()` – klockan och dygnets planer (ankomster, incidenter, besök, väder, tåg, VIP) görs om och slumpen seedas om ur dygnets frö, men huset fortsätter: `S.t`, hissarna, folket, fel/linbyten, pågående incidenter och chefens beslut om dem. Gårdagens statistik i `S.yesterday`; sammanfattningen öppnas som vyn `yesterday` i panelen (informationsrutan ”Dag n börjar”). Varje delsystem har en `…Roll()` bredvid sin `…Reset()` (`lifeRoll`, `visitsRoll`, `chiefRoll`, `crewRoll`: nattskiftet `p.shiftEnd` går när dagskiftet är i huset). `'ny'` (bara standard i `newSim`, testerna och ligan) = spelet stannar för sammanfattningen och `resetDay()` börjar om; bara slitaget och ohjälpta hissfel (`keptFault`/`restoreFault` i service.js) följer med. Klockslag som sparas på personer (`p.returnAt`, rutiner) gäller dygnet de skapades – nya sådana fält måste flyttas i `…Roll()`.
- **Dygnets tempo** står i `TEMPOS` (config): sekunder per del av dygnet. Spelet har bara det långa dygnet (~15 min, `lang`) där rusningarna och lunchen får mest tid; det korta 6-minutersdygnet (`kort`) finns kvar för testerna, ligan och `npm run bench`. Tempot väljs i `newSim` (`setTempo`), sparas i `S.tempo`. `timeScale(h)` = klockans takt, `pace(h)` = takten mot 6-minutersdygnets dag: flöden som ska följa speltiden (besökare, bud, incidenter) multipliceras med den, anställda med `pace ** EMP_K` (sim.js), slitaget med `tempoWear()`. Hissar och gång sker i verklig tid, så en resa genom huset tar en halv till en speltimme – planera efter det (öppettider, hemgång på natten). Vistelser i rummen (`p.timer` i läget `office`) räknas i speltid via `activityRate(h)`. Gränssnittet visar ingen klocka, bara ☀️/🌙.
- **Simuleringsmoduler importerar aldrig** `render/view/hud/input/scenery`.
- **Allt spelaren gör som påverkar simuleringen går via `act()`** (actions.js) – gränssnittet ändrar aldrig simuleringens tillstånd direkt. Platsbeläggningen ligger i `S.occ`, aldrig i config-datan.
- **Huset är data.** Lägg till/ändra våningar och hissar i `BUILDING`; använd härledda värden (`LOBBY`, `SKY`, `ROOF`, `DOCK`, `STATION`, `HOME_FLOORS`, `idx('7')`, `floorWith('bank')`) – hårdkoda aldrig våningsindex. Index ≠ etikett: index 0 är tunnelbanestationen `TB`, `fl(i)` ger etiketten.
- En hiss stannar bara på `e.stops`, stannar aldrig utanför `minF..maxF`, kör aldrig över `e.ratedKg`, och åker aldrig förbi en passagerares mål.
- **Dubbeldäck:** hissens läge (`e.pos`, `e.floor`, `carCalls`, `pick`, `stops`) räknas alltid i nedre däckets våningar; folkets våningar (`p.floor`, `p.dest`, `e.serves`) är riktiga våningar. Översätt med `posOf(e, f)` (personens våning → korgens läge) och `deckFloor(e, p, f)`, och låt en hiss bara köra inom ett däck (`e.legs`).

## Domänbegrepp

- `p.goal` = slutmål, `p.dest` = nuvarande delresa (kan vara `SKY` för hissbyte). `p.exitFloor` = var personen lämnar huset (E, garage, lastkaj eller stationen `STATION`).
- Tunnelbanan: stationen (`TB`) ligger under P2. Stationsexpressen X1 (egen grupp `tbana`) går TB ⇄ E ⇄ 6 med övre däcket P2 ⇄ 1 ⇄ 7; låga zonen och varuhissen går också ner. Den som ska med tåget går ut på perrongen (`p.toTrain`, läget `platform`) och kliver på när tåget står inne; de som kliver av har `p.fromTrain` (syns från tågets dörr i hallen). Perrongen ritas i `drawPlatformPx` (pixhall.js).
- Personer: `kind` = `emp` / `vis` / `staff` / `res` (boende, stannar över natten), `role` för nattpersonal/bud, `vip`. Husets personal har `crewId` (crew.js); deras resor inom huset har `leaving = false` (entrén är deras utgång). Platser med `post`, `where` eller `brk` väljer ingen annan (`pickSpot`).
- Last ≥ 22 kg → bara varuhissen; varuhissen tar bara last och personal (`elevatorAllows`).
- Driftchefen: `newSim(seed, { chief, chiefStrat, incLevel })` – chefen är på från början; `autoInc: true/false` betyder slumpen Normalt/Av som förr.
- Styrlogiker (`S.strategy`): `smart`, `peak` (Rusning), `eco` (Energisnål), `nearest`, `random`, `buttons`. `costBased()` = de tre som använder kostnadsfunktionen.
- Hisslägen (`e.mode`): `normal`, `recall`, `locked`, `rescue`, `dead`, `lift` (panoramahissen kör ett flyttlass; `e.liftWant` = beställd, tar inga nya), `broken` (trasig, väntar på tekniker; `e.fault.cable` = linbyte, korgen står mellan två våningar), `service`, `snapped` (linbrott: `e.snap.ph` = `fall`/`trapped`/`evac`). `e.hold` = på väg till nattservice (tar inga nya). `e.hijack` = kapad av rånarna under kuppen (tar inga nya, heist.js). `e.wear` följer med till nästa dygn. `outReason(e)` = varför hissen inte tar nya ('' = den tar), grunden för `operational`/`servesNow`/`outLong`. `benched(e)` = tar inga nya just nu (`e.off`, `e.hot`, `e.windLock`, `e.wetLock` – vattenläckan); `e.indep` = oberoende drift (bara flyttgubbarna och ambulansen).
- `keyed(p)` = har nyckel och använder aldrig hallknapparna (VIP, ambulans, flyttgubbar); `prio(p)` = får en hiss för sig (VIP-låset: VIP och ambulans).
- Hissetikett: `p.space` (hur trångt man står ut med, 9 = bryr sig inte), `p.polite` (håller upp dörren). Ett fullt däck hämtar ingen (`e.deckFull`).
- Mellanplanet `MEZZ` (våning 1): dit åker man rulltrappa från entrén till expressens övre däck (`p.escalator`).
- Trappan: `stairsChoice` (korta resor/otåliga, `p.fit`), `p.stairsByChoice` skiljer frivilliga trappresor från utrymning m.m.
- Brandlägen: `recall` (larmets standard) / `zone` / `none` (`startFire(f, false)` startar utan återkallning); i zonläge spärras hissar som inte når någon säker våning (`e.zoneLock`).
- Nytt våningstema = post i `THEME_INFO` (config) med namn, `acc` i Kontor 95-tappning och platser – hallen ritas automatiskt.

## Arbetssätt

- **Kör `npm run quick` lokalt före varje commit** (även när ändringen ser liten ut) och **hela `npm run check` innan något hamnar på `main`** och efter ändringar i styrningen (`dispatch.js`, `buttons.js`, `elevators.js` – de statistiska jämförelserna mellan styrlogikerna körs bara där). CI körs bara på `main` och i pull requests och ska inte vara det som hittar felen. Snabbläget i sviten: `test(namn, fn, { slow: true })` hoppas över, `some(lista, n)` = de n första; ett nytt tungt test (många hela dygn) ska ha ett snabbläge.
- Kör testerna efter ändringar i simuleringen. Ändras beteendet avsiktligt larmar facit-testet – kontrollera skillnaden och kör sedan `npm run golden`.
- Ändringar i styrningen mäts med `npm run league -- 40 --save=fore` före och `--cmp=fore` efter. Ett dygn sprider ±1,5 s i snittväntan, så små skillnader är brus. Mer exakt ETA ≠ kortare väntan (se kommentaren i `eta()`).
- Typerna: personer är `Person` (people.js), hissar `Elevator` (elevators.js) och incidenternas tillstånd har var sin typ i sin modul (`Fire`, `Outage`, `Pano`, `Move` …, se `S` i state.js). `S` och `S.stats` är stängda: alla fält deklareras i `INIT` respektive `newStats()` i state.js (även de som bara ett delsystem använder, som `S.train` och `S.autos`). Ett nytt fält på `S`, i statistiken, på en person eller hiss läggs till där – annars larmar `npm run typecheck`. Funktioner som tar en person eller hiss får `@param {Person} p` / `@param {Elevator} e`.
- Nya simuleringsfunktioner får ett test i `tests/suite.js`; regler som alltid ska gälla läggs i `watcher()` (kontrolleras varje steg över 40 slumpade dygn och över 24 dygn med slumpade spelaråtgärder). Ny spelaråtgärd = post i `ACTIONS` (actions.js) och i `PLAYER_ACTIONS` (suite.js). **Ny incident** = en egen modul med egen slumpström, ett fält på `S` (state.js) och en post sist i `systems()` (systems.js: tick/reset, `on`, `trigger`, `weight` för tidtabellen, förvarningen, `chief` om den har val); sedan gränssnittet: kortet i `incidentHtml` (hud.js) med `chiefLine(nyckel, …)`, regissören, knappen i *Framkalla* (panels.js), steget i Murphys lag (chaos.js) och texterna i `lang-en.js`. Kortets knappar `data-act="nyckel:val"` når `act(nyckel, val)` utan egen rad i input.js. Har den val: beslutet i `chief.js` (med skäl, exporteras och kopplas in som `chief.tick`). Testernas `sim()` har driftchefen på rast (`chief: false`) om inget annat sägs; dockhustestet kör kaosdygn utan spelaren och kräver att incidenterna tar slut av sig själva.
- Kontrollera grafik i webbläsaren. `?prof=1` visar tid per del av bildrutan (simulering, hallar, folk, text, lager som ritas om …) uppe till vänster i bilden (`prof.js`; nya delar mäts med `lap('namn')`) – fungerar även på mobilen. För att spola fram tiden i konsolen: `const st = await import('/src/state.js'), sim = await import('/src/sim.js'); while (st.hour() < 21) sim.step(sim.DT);`
- Ny text som visas för spelaren skrivs på svenska i koden och får en engelsk mall i `lang-en.js` (samma värden `{0}` …). Låt värden vara hela ord: inte svenska ändelser som eget värde (`hiss${n > 1 ? 'ar' : ''}`) eller en bokstav för sig – skriv hela orden i båda grenarna. Testet Språket kör ett kaosdygn och kräver att loggen och dagböckerna blir engelska.
- Höj `?v=` på `style.css` i `index.html` när CSS ändras.
- Det som har gjorts står i `CHANGELOG.md`. Planerade tekniska förbättringar står i `TODO.md` och idéer till spelet som inte är byggda i `IDEER.md` – stryk det som blir gjort.
